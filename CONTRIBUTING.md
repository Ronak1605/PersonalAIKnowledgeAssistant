# Contributing Guidelines

Thank you for your interest in contributing! Please follow the guidelines below when contributing.

## Branching Strategy
- `main`: Stable, production-ready code
- `feature/*`: New features
- `fix/*`: Bug fixes
- `docs/*`: Documentation updates
- `test/*`: Adding or editing tests
- `refactor/*`: Code change that neither fixes a bug nor adds a feature
- `chore/*`: Tooling or maintenance

## Commit Message Guidelines
This project follows the commit specifications defined below.

### Commit Format
`<type>: <short description>`

### Allowed Types
- `feat`: New feature
- `fix`: Bug fix
- `docs`: Documentation only
- `refactor`: Code change that neither fixes a bug nor adds a feature
- `test`: Adding or editing tests
- `chore`: Tooling or maintenance

### Examples
- feat: add PDF document loader
- fix: handle empty input files
- docs: add architecture overview
- refactor: extract embedding service

## Pull Requests
- All changes must go through a Pull Request
- Keep PRs focused and small
- Link related issues where possible
